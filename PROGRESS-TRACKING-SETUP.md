# Progress tracking setup

The platform stores each user's history in three separate named Firestore databases:

- `virtual-labs` for explicitly marked lab completions
- `ai-interviews` for the evaluation reports generated by the current interview page
- `e-library` for downloaded personal reading-notes templates

Each event is stored at `users/{uid}/history/{entryId}` in the corresponding database. The browser only reads and writes the signed-in user's documents. Firebase Admin is used by the server for email notifications and weekly summaries.

## Firebase setup

1. In Firebase Console, enable the Google, email/password, and phone sign-in methods used by the site.
2. Create the three Firestore databases with the exact IDs above. Choose a location appropriate for your users; Firestore database locations cannot be changed after creation.
3. Install and authenticate the Firebase CLI if you have not already:

   ```powershell
   npm install --global firebase-tools
   firebase login
   firebase use --add
   ```

   Select the Firebase project `virtual-learning-platfor-1e5ab`.
4. From the project root, deploy the three rulesets configured in `firebase.json`:

   ```powershell
   firebase deploy --only firestore
   ```

The databases must exist before deploying their rules. The rules allow a signed-in user to read their own history and create validated events only; client-side updates and deletes are denied.

## Server credentials and email

The Node server uses Firebase Application Default Credentials. For local development, create a service account credential in Firebase Console and keep its JSON file outside the repository. Set the following in the PowerShell session that starts the server:

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\secure\firebase-service-account.json"
$env:RESEND_API_KEY = "re_your_key"
$env:RESEND_FROM_EMAIL = "Progress updates <verified-sender@example.com>"
npm start
```

In production, prefer the hosting provider's attached service identity instead of a downloaded service-account key. Verify the sender domain/address with Resend before sending. Never commit credentials or add them to client-side code.

An event notification is attempted immediately after an event is saved. The server also sends a summary for the preceding seven days every Monday at 09:00 `Asia/Kolkata`; the Node process must remain running for this in-process schedule to execute. Users authenticated only by phone without an email can still have saved history but cannot receive email.

## Current history behavior

- On a lab page, a signed-in user must choose **Mark lab complete**; the platform does not infer completion or assign a lab score.
- The AI Interview history records the score and grade currently generated by the page's predefined report data. It is not a score calculated by executing the edited code.
- The E-Library catalog currently does not provide downloadable book files. **Download notes** creates an original blank reading-notes template and records that file; it does not download the listed textbooks.
